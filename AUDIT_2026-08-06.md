## Critical findings

### C-1 — Коллизии путей RPA тихо перезаписывают извлечённые данные

Места: `src/archive/rpa.rs:293-323`, `src/archive/rpa.rs:591-629`, `src/output.rs:75-82`, `src/output.rs:196-207`.

`extract_rpa` группирует фрагменты по исходной строке `entry.path`, но не проверяет уникальность итогового filesystem path. На Windows `Case.txt` и `case.txt` указывают на один файл. Пары `a//b`/`a/b`, `a/./b`/`a/b` и `a\b`/`a/b` также становятся одним путём после `safe_join`. Последующая atomic rename заменяет предыдущий результат; счётчик остаётся счётчиком записей архива, а не реально уникальных файлов.

Подтверждённый результат:

```text
Extracted "collision.rpa" (2 entries, 10 bytes uncompressed)
Done. Wrote 1 files.
exit code: 0
output: только case.txt, bytes = "lower"
```

Минимальный генератор корректного RPA3:

```python
from pathlib import Path
import pickle, zlib

def write_rpa(path, entries, key=0x42424242):
    body = bytearray()
    index = {}
    offset = 34
    for name, payload in entries:
        index[name] = [(offset ^ key, len(payload) ^ key, b"")]
        body.extend(payload)
        offset += len(payload)
    header = f"RPA-3.0 {offset:016x} {key:08x}\n".encode("ascii")
    assert len(header) == 34
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_bytes(header + body + zlib.compress(pickle.dumps(index, protocol=2)))

write_rpa(
    Path("repro/source/collision.rpa"),
    [("Case.txt", b"UPPER"), ("case.txt", b"lower")],
)
```

Команда: `renpyex extract repro/source --out repro/out --rpa`.

Исправление: до первой записи построить отображение `normalized destination → source entries`, учитывать семантику целевой файловой системы, отклонять любую неоднозначность целиком и сообщать оба исходных имени. Для архивов нужен preflight, чтобы ошибка не оставляла частично извлечённое дерево.

### C-2 — Конвертация разных изображений в один формат тихо оставляет только последнее

Места: `src/cli.rs:504-535` и симметричный GUI путь `src/gui/ops.rs:269-313`.

`with_extension("png")`/`with_extension("jpg")` делает одинаковый destination для разных форматов с одинаковым stem. Проверки коллизий нет, `write_atomic` заменяет предыдущий результат, а `converted` увеличивается для обеих записей.

Reproducer:

```powershell
# Поместить два валидных изображения с различными пикселями:
# repro\source\same.png и repro\source\same.jpg
renpyex convert repro\source --out repro\out --to png
Get-ChildItem repro\out
```

Подтверждено: `Converted: 2, skipped (non-image): 0, failed: 0`, но создан один `same.png`.

Исправление: общий для CLI и GUI preflight всех destination; при коллизии завершаться до записи. Альтернатива — детерминированно добавлять исходное расширение к имени, но это изменение публичной схемы выходных путей и должно быть явно задокументировано.

## Important findings

### I-1 — `extract` без `--rpa` пропускает сам архив и завышает число записанных файлов

Места: `src/cli.rs:353-362`, `src/cli.rs:384-434`; та же логика в `src/gui/ops.rs:119-147`.

CLI описан как копирующий файлы, а `--rpa` — как «also extract contents». Реализация без флага не копирует `.rpa` вообще. `total` вычисляется до пропуска и затем печатается как число записанных файлов.

Reproducer:

```powershell
New-Item -ItemType Directory repro\only-rpa
Copy-Item tests\fixtures\sample.rpa repro\only-rpa
renpyex extract repro\only-rpa --out repro\out
Get-ChildItem repro\out -Recurse
```

Подтверждено: выход пуст, но процесс печатает `Done. Wrote 1 files.` и возвращает 0.

Исправление: всегда копировать архив как обычный входной файл; `--rpa` должен только добавлять распаковку содержимого. Считать `written` после успешной записи, отдельно выводить `copied/skipped/unpacked/failed`.

### I-2 — Основное извлечение RPA имеет незаявленную runtime-зависимость от Python

Места: `src/archive/rpa.rs:428-492` против `README.md:43-44`.

Индекс каждого RPA2/RPA3 передаётся в `python -c`/`python3 -c`. Это не только optional `.rpyc` path: без Python не работает основная функция распаковки. README одновременно заявляет «No runtime dependencies. Python is only needed ... for unrpyc».

Reproducer: запустить release binary по абсолютному пути с дочерним `PATH`, не содержащим Python, и выполнить `extract ... --rpa`. Подтверждён exit code 1 с `failed to launch`.

Исправление: либо реализовать ограниченный pickle decoder в Rust, либо поставлять/проверять Python как обязательную зависимость и исправить README, installer/GUI diagnostics и release packaging. Это архитектурный выбор, а не косметическая правка.

### I-3 — RPA2 с Python-2 non-ASCII именами не читается

Места: Python helper `src/archive/rpa.rs:437-463`.

`SafeUnpickler(io.BytesIO(data))` использует Python 3 default `encoding="ASCII"`. Типичные Python-2 pickle строки с байтом `\xe9` поэтому завершаются ошибкой; ASCII RPA2 проходит. Даже для успешно загруженных byte keys `str(k)` не является декодированием имени.

Reproducer: создать RPA2 индекс в Python 2 через `pickle.dumps({'caf\xe9.txt': [(offset, length)]}, 2)`. Подтверждено: `cafe.txt` ASCII извлекается, `caf\xe9.txt` завершается ошибкой ASCII decode.

Исправление: определить точную политику имён Ren'Py/Python 2; загружать legacy strings через `encoding="bytes"` или `latin1`, передавать имя в lossless encoding (например, tagged hex/base64), а в Rust выполнять явную платформенную материализацию или диагностируемый отказ.

### I-4 — `--key` применяет лишний XOR и ломает официальный RPA3

Места: `src/archive/rpa.rs:519-527`, описание `src/cli.rs:60-62`.

Официальный writer уже XOR-ит offset/length ключом из заголовка, а официальный reader XOR-ит только этим ключом. RenpyEx при указанном пользователем ключе использует `user_key ^ archive_key`.

Reproducer: с генератором из C-1 создать один файл и key `0x42424242`:

```powershell
renpyex extract repro\source --out repro\ok --rpa
renpyex extract repro\source --out repro\bad --rpa --key 42424242
```

Подтверждено: без `--key` официальный архив извлекается байт-в-байт; с тем же правильным ключом команда падает. Официальное поведение: [archiver.rpy:74,83](https://github.com/renpy/renpy/blob/da4d86679ceca69124dc2204098e1245968c9aa0/launcher/game/archiver.rpy#L74-L83) и [loader.py:175-181](https://github.com/renpy/renpy/blob/da4d86679ceca69124dc2204098e1245968c9aa0/renpy/loader.py#L175-L181).

Исправление: обычный RPA3 всегда декодировать header key. Если `--key` нужен для повреждённого/нестандартного архива, он должен явно **заменять**, а не дополнительно XOR-ить header key; семантику и тест с ненулевым официальным ключом закрепить.

### I-5 — Размеры RPA и subprocess не ограничены; возможны memory exhaustion и вечное ожидание

Места: `src/archive/rpa.rs:398-406` и `src/archive/rpa.rs:437-503`.

Код без лимитов:

1. читает весь сжатый хвост архива в память;
2. распаковывает zlib до произвольного размера;
3. отправляет всё Python;
4. ждёт процесс без timeout;
5. принимает весь stdout/stderr через `wait_with_output`.

`SafeUnpickler.find_class` блокирует globals, но не ограничивает размер контейнеров, строк, чисел или CPU. Локально подтверждено линейное потребление памяти на искусственно расширяемом индексе; путь не содержит cap или deadline.

Безопасный reproducer масштаба: подать индекс `zlib.compress(pickle.dumps({"x": [(34, 1)]} | {str(i): [] for i in range(N)}))` и увеличивать `N` под process memory monitor. Для проверки зависания заменить найденный `python` wrapper-ом, который читает stdin и не завершает работу: RenpyEx deadline не имеет.

Исправление: лимиты compressed bytes, decompressed bytes, entries, tuples, path/prefix length и helper output; streaming `take(limit + 1)`; timeout с завершением всего process tree; отказ до выделения по заявленным размерам.

### I-6 — Заявленная проверка целостности не соответствует реализации

Места: `src/verify/mod.rs:95-131`, `src/verify/magic.rs:1-5`, `src/lib.rs:4-6`, `src/cli.rs:43-78`, `README.md:25-27` и `README.md:68-74`.

Подтверждены три независимых расхождения:

1. `verify_one` вычисляет magic и немедленно выбрасывает результат (`let _ = ...`); несовпадение расширения, unknown и truncation не влияют на outcome.
2. Файл только из восьми байтов PNG signature с соответствующим hash принимается как `Ok`.
3. `extract` не создаёт `SHA256SUMS.txt`; документированная следующая команда `verify ./extracted` сразу падает из-за отсутствующего manifest.

Безопасный reproducer пункта 2:

```powershell
New-Item -ItemType Directory repro\verify
[IO.File]::WriteAllBytes(
  (Join-Path $PWD 'repro\verify\truncated.png'),
  [byte[]](0x89,0x50,0x4e,0x47,0x0d,0x0a,0x1a,0x0a)
)
$hash = (Get-FileHash repro\verify\truncated.png -Algorithm SHA256).Hash.ToLowerInvariant()
[IO.File]::WriteAllText(
  (Join-Path $PWD 'repro\verify\SHA256SUMS.txt'),
  ("$hash  truncated.png" + [Environment]::NewLine),
  [Text.Encoding]::ASCII
)
renpyex verify repro\verify
```

Подтверждено: `Verified 1 / 1`, exit 0.

Исправление: разделить и точно назвать две гарантии. Hash verification должен проверять manifest; format validation должен возвращать отдельный structured outcome и реально влиять на exit code. Для доказательства «до/после extraction» manifest должен создаваться из доверенного источника до записи и проверяться после неё; manifest, созданный только из выхода, не доказывает целостность.

### I-7 — SDK adapter генерирует несуществующий `--enable_all`

Место: `src/sdk.rs:225-238`.

Fake SDK записал точный argv: RenpyEx передаёт `--enable_all`. Официальный Ren'Py принимает `--enable-all`.

Reproducer: `renpyex sdk <project> --sdk <fake-sdk> test --enable-all` с Python launcher, печатающим `sys.argv`. Подтверждён underscore-вариант. Официальный источник: [testexecution.py:983-989](https://github.com/renpy/renpy/blob/da4d86679ceca69124dc2204098e1245968c9aa0/renpy/test/testexecution.py#L983-L989).

Исправление: заменить строку на `--enable-all` и добавить integration test fake launcher → exact argv для каждого `Action`, а не только unit test внутренних vectors.

### I-8 — SDK timeout не ограничивает реальное время и может зависнуть навсегда

Места: `src/sdk.rs:104-152`, `src/sdk.rs:174-195`.

По deadline убивается только непосредственный child. Затем main thread без timeout делает `join` двух reader threads. Если descendant унаследовал stdout/stderr, pipe не получает EOF после убийства parent.

Подтверждённый тест: fake SDK parent запускает descendant на 4 секунды и остаётся живым; при `timeout = 1s` вызов вернулся лишь через 4,33s. Descendant без конца делает ожидание бесконечным.

Исправление: создавать отдельную process group/job object, по timeout завершать всё дерево, закрывать локальные pipe handles и ограничивать join. На Windows использовать Job Object с kill-on-close; на Unix — process group + `killpg`. Для каждого target нужен integration test с start-gun descendant, который удерживает pipe.

### I-9 — Автообнаружение `unrpyc` на PATH возвращает неправильный путь

Места: `src/archive/rpyc.rs:30-48` и `src/archive/rpyc.rs:93-106`.

`where/which` успешно находит executable/script, но stdout отбрасывается. Затем запускается `python unrpyc destination.rpyc`. Python ищет относительный файл в current directory, а не найденный PATH entry.

Reproducer: положить рабочий `unrpyc` только в отдельный каталог PATH, убедиться, что `where unrpyc` успешен, затем вызвать extraction с `--rpyc` без `--unrpyc`. Подтверждено: discovery возвращает `Some`, но Python сообщает, что не может открыть относительный `unrpyc`.

Исправление: разобрать первый абсолютный результат `where/which` и передать его Python; если найденный объект является самостоятельным executable, запускать его напрямую. Добавить процессный тест, где current directory не совпадает с PATH directory.

### I-10 — GUI помечает partial failure как `done` и не стримит журнал

Места: документированный контракт `src/gui/ops.rs:5-10`, extraction `src/gui/ops.rs:104-214`, verify `src/gui/ops.rs:219-254`, status `src/gui/app.rs:174-190`.

GUI operations возвращают `Ok(log)` при hash mismatch и сломанном RPA. `poll` любой `Ok` превращает в status `done`. Весь log строится в String и посылается одним сообщением после завершения, поэтому длительная операция не показывает прогресс.

Подтверждено реальными вызовами:

- manifest с неверным hash → `ops::verify(...).is_ok()` и log содержит `MISMATCH`;
- broken `.rpa` → `ops::extract(...).is_ok()` и `Done with 1 failures.`;
- app-path для обоих ставит `done`.

Исправление: возвращать тип `OperationReport { log, failures }` либо `Err` для любой неполной операции; `poll` ставит success только при `failures == 0`. Для прогресса нужен отдельный channel событий, а final result — отдельное terminal message.

### I-11 — Doctor неверно связывает переводы, распознаёт диалог как asset и выдаёт нестабильный JSON

Места: `src/doctor.rs:364-480`, `src/doctor.rs:500-572`, `src/doctor.rs:753-780`, обещание `src/doctor.rs:330-332`.

Подтверждены четыре ошибки:

1. terminal `old "Hello"` создаёт `TranslationError`, но `missing_new` остаётся 0, потому что `finish_translations` не увеличивает `w.missing`;
2. `pending` хранится на язык, а не на файл: `old` в `a.rpy` ошибочно закрывается `new` из `b.rpy`;
3. валидная реплика `e "show images/missing.png"` считается asset statement и даёт missing reference/exit 1;
4. `refs` — `HashMap` и потребляется без сортировки; на одном и том же fixture 12 отдельных процессов дали 12 разных JSON byte streams.

Reproducer для первых двух:

```text
game/tl/french/a.rpy: old "from a"
game/tl/french/b.rpy: new "from b"
```

`doctor` сообщает 0 translation errors вместо missing pair. Для terminal `old` сообщает error, но counter 0.

Исправление: translation state сбрасывать/финализировать на границе каждого файла; terminal pending одновременно добавляет error и counter; statements разбирать хотя бы контекстно-токенным lexer вместо `contains` по всей строке; все сериализуемые collections делать `BTreeMap` или явно сортировать по стабильному composite key перед JSON.

## Minor findings

### M-1 — Parser/emitter `SHA256SUMS` не является coreutils-compatible

Места: `src/verify/mod.rs:50-70` и `src/verify/mod.rs:134-151`; claim `README.md:26`.

`trim` уничтожает граничные пробелы имени, escaped filename marker не разбирается, newline/backslash escaping не поддержан, manifest читается только как UTF-8, а emitter использует lossy `Path::display()`. Поэтому валидные Unix filenames не round-trip.

Reproducer: передать `parse_sums` строку с именем `" leading"` или coreutils escaped entry; полученный Path отличается либо parse завершается ошибкой. На Unix создать non-UTF filename и вызвать `emit_sums` — исходные bytes имени не сохраняются.

Исправление: реализовать точную grammar coreutils в bytes/`OsStr` для каждого target либо убрать claim и явно назвать поддерживаемый UTF-8 subset.

### M-2 — Walker молча пропускает non-UTF имена и классифицирует только по первым 16 байтам

Места: `src/archive/walker.rs:108-136`.

На Unix `to_str() == None` приводит к `continue` без warning. Кроме того, первые 16 printable bytes достаточны, чтобы поздний binary/NUL content никогда не попал в detector sample; это даёт misleading `Text` в info/Doctor.

Reproducer: на Unix создать файл с `OsString::from_vec(vec![0xff])` — inventory его не содержит. Для sampling создать binary, начинающийся 16 ASCII-байтами и затем NUL: `info` классифицирует его по усечённому prefix.

Исправление: хранить `PathBuf/OsString` losslessly и выдавать диагностируемую ошибку там, где нужен UTF-8; для text sniff читать достаточную bounded выборку или не заявлять content-level text classification.

### M-3 — Публичный `FormatQuality` нарушает собственный диапазон `1..=100`

Места: `src/convert/image.rs:24-26` и `src/convert/image.rs:73-78`; CLI проверяет отдельно в `src/cli.rs:490-494`.

`FormatQuality(pub u8)` позволяет `0` и `255`; `convert_to_jpeg` их принимает. GUI передаёт raw config value в `src/gui/ops.rs:290-292`.

Reproducer: `convert_to_jpeg(valid_png, FormatQuality(0))` подтверждённо возвращает `Ok`, хотя публичная документация запрещает 0.

Исправление: private field + checked `TryFrom<u8>`/constructor; CLI и GUI используют один валидатор. Добавить boundary tests 0, 1, 100, 101, 255.

### M-4 — Два произвольных байта `ff e0` классифицируются как MP3

Место: `src/verify/magic.rs:149-152`.

Frame sync требует проверки дополнительных зарезервированных/валидных полей и достаточной длины header. Сейчас `detect(&[0xff, 0xe0]) == Magic::Mp3Frame`.

Reproducer: записать два байта `ff e0` и выполнить `info` либо вызвать `detect` напрямую; подтверждён `Mp3Frame`.

Исправление: требовать полный MPEG audio header и валидировать version/layer/bitrate/sample-rate bits; добавить negative boundary vectors.

### M-5 — В production оставлен явный phantom/dead marker

Место: `src/archive/rpa.rs:651-653`.

`#[allow(dead_code)] const _: () = ();` с комментарием «reserved for future cross-checks» ничего не проверяет и создаёт ложное впечатление будущего invariant.

Reproducer: статический — удаление блока не меняет ни один symbol, build или test.

Исправление: удалить блок; будущую проверку добавлять только одновременно с её реализацией и тестом.
