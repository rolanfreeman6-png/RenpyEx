## 2. Побайтовая сверка формата RPA с настоящим Ren'Py

Сверено с `renpy/loader.py` и `launcher/game/archiver.rpy` реального SDK 8.5.3:

- **Заголовок v3:** loader читает `l[8:24]` (offset, hex) и `l[25:33]` (key, hex) —
  `parse_v3_header` в `src/archive/rpa.rs:453` парсит идентичные срезы. ✅
- **Деобфускация:** loader делает `(offset ^ key, dlen ^ key)` и для 3-tuple
  `(offset ^ key, dlen ^ key, start_to_bytes(start))` — код делает тот же XOR
  (`rpa.rs:934-940`), `--key` корректно **заменяет** ключ заголовка. ✅
- **Префиксы:** `start_to_bytes` кодирует str→latin-1, bytes не трогает — helper
  делает то же (str→latin-1, bytearray→bytes). ✅
- **v2:** loader читает 24 байта, `int(l[8:], 16)`, key=0 — `parse_v2_header` эквивалентен. ✅
- **Архиватор пишет pickle с HIGHEST_PROTOCOL** (archiver.rpy:80) — на Py3 это ≥4,
  что подтверждает допустимость SafeUnpickler (см. п. 5.5).
- **Флаги SDK** `--error-code`/`--all-problems` (lint.py:1077,1098), `--enable-all`/
  `--report-detailed` (testexecution.py:943,982), `--keep-orphan-rpyc`

  `--strings`/`--text` (dialogue.py) — все существуют в реальном SDK. ✅

## 5. Новые находки (все Minor, ни одна не портит данные)

1. **UX — `info` молча глотает ошибки `list_rpa`** (`src/cli.rs:325`, `if let Ok`):
   на битом архиве печатается «Archive detected: …» без строки деталей и без ошибки,
   exit 0. Воспроизведено на архиве с битым magic. Рекомендация: выводить причину в stderr.
2. **UX — `sdk` требует абсолютный путь проекта**: child-процесс запускается с
   `current_dir(sdk_dir)`, поэтому относительный путь резолвится внутри SDK →
   «Base directory …/renpy-8.5.3-sdk/TestGame does not exist». Воспроизведено.
   Рекомендация: канонизировать путь проекта до spawn.
3. **UX — при неудаче SDK stdout отбрасывается**: ошибка включает только stderr, а
   lint-отчёт (977 байт диагностики на stdout) пропадает. Воспроизведено. Рекомендация:
   включать обрезанный stdout в сообщение об ошибке.
4. **UX — extract на файле вместо каталога** даёт системное «Неверно задано имя папки
   (os error 267)» вместо внятного «not a directory» (`doctor` такую проверку делает,
   `extract` — нет).
5. **Совместимость (крайний случай)**: архивы, запикленные Python 3 с protocol 2–3 и
   bytes-префиксами, отклоняются SafeUnpickler («global objects are not permitted» —
   pickle кодирует bytes через глобал `_codecs.encode`). Настоящий Ren'Py такие не
   создаёт (Py2-архиваторы пишут str, Py3 — HIGHEST_PROTOCOL), но сторонний упаковщик
   может. Осознанный компромисс безопасности; альтернатива — точный allowlist
   `_codecs.encode`.
6. **Политика лимитов декодера неявная**: 512 MiB-кап приходит из дефолта зависимости
   `image` (max_alloc), а не из политики renpyex (в коде нет `set_limits`); ширина/высота
   не ограничены. Не эксплуатируется (проверено бомбой), но явный лимит был бы устойчивее
   к смене дефолтов зависимости.
7. **Документация `--rpyc`**: декомпилируются только свободные `.rpyc` дерева; `.rpyc`
   внутри распакованных `--rpa` архивов не декомпилируются даже при обоих флагах
   (`cli.rs:424-443` итерирует `inv.files`). Похоже на осознанный дизайн, но в README
   не оговорено.
